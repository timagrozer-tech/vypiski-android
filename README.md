# REVVL Camera Lab v0.3.9

**Экспериментальное автономное Android-приложение камеры на Kotlin** для REVVL 7 Pro 5G (Snapdragon 6 Gen 1 / 8 ГБ / Android 16) и других Android-устройств, предоставляющих Camera2/CameraX API. Это собственный проект, **не** Google Camera и **не** порт Google HDR+.

## Возможности

- JPEG-фото в галерею без передачи данных в интернет.
- Доступные системные OEM-расширения HDR, Night, Bokeh (не гарантированы на конкретной прошивке).
- Ultra HDR (JPEG_R), RAW (DNG)+JPEG, если явно объявлены возможностями CameraX для объектива.
- Видео с выбором доступного качества (включая 4K только при поддержке), запись со звуком по разрешению.
- Фокус касанием, зум, регулировка EV, вспышка, ручные ISO/выдержка с `MANUAL_SENSOR`.
- Таймер на 0/3/10 секунд, сетка 3×3, запоминание выбранного формата, таймера и сетки.
- Диагностика реальных Camera2-характеристик: список публичных объективов, RAW, ограничения выдержки и ISO, OIS, размеры, доступное видео, OEM-расширения.
- **Новое в 0.3: «СТЕК ×3»** — экспериментальная локальная многокадровая обработка трёх JPEG с выравниванием небольшого глобального сдвига и отсечением различающихся пикселей. Результат сохраняется отдельным JPEG.

## Режим «СТЕК ×3»

1. Выбери задний или фронтальный объектив, затем в ряду режимов нажми **СТЕК ×3**.
2. Держи телефон как можно неподвижнее, наведи его на статичную сцену и нажми **СНЯТЬ**. Приложение получит три последовательных снимка.
3. Алгоритм (v2) использует средний снимок как опорный, оценивает общий сдвиг до 64 пикселей по пирамиде, выравнивает небольшой дрейф экспозиции, отбрасывает несовпадающие блоки 16×16 и пиксели, усредняет в приближённо линейном свете и сохраняет результат в `DCIM/REVVL Camera Lab`. В строке статуса — оценка снижения шума и время обработки.
4. **A/B:** в режиме СТЕК кнопка формата становится **A/B: ВКЛ/ВЫКЛ**. Когда A/B включён, рядом с результатом сохраняется опорный кадр без обработки `…_REF.jpg` — того же размера и сжатия, так что разница между файлами показывает только эффект слияния.
5. Для снижения расхода памяти размер обработанного кадра ограничен длинной стороной **2304 пикселя**. При сильной тряске, движущихся людях и очень тёмной сцене результат может быть хуже обычного кадра.

**СТЕК ×3 не равен Night Sight, RAW-фьюжну, длинной экспозиции или настоящему HDR.** Съёмка выполняется без изменения экспозиции между кадрами. В этом режиме временно отключаются OEM HDR/Night, RAW, Ultra HDR, вспышка и ручные ISO/выдержка. Для максимально большого оригинального снимка вернись в обычный режим JPEG/RAW.

Все 95 вызовов есть в сигнатурах 1.7.0-rc01, устаревших среди них нет; тесты и проверка типов проходят. Инструкция — `migrations/camerax-1.7/README.md`.

## Изменения 0.3.8 — исправления по полному ревью кода

CameraX 1.7 ещё не стабильна (1.7.0-rc01), поэтому вместо обновления — сквозной ревью `MainActivity` после семи этапов правок. Найдено и исправлено:

1. **Возможное падение при выходе**: колбэк «фото сохранено» / «видео финализировано» после `onDestroy` отправлял загрузку миниатюры в остановленный executor (`RejectedExecutionException` в главном потоке).
2. **Фиксация AE/AF во время записи видео** блокировалась проверкой «занят» — теперь доступна (запрещена только во время фото, серии, таймера и проверки сочетаний).
3. **После «Домой» / блокировки экрана** фонарик в видео гас, а кнопка показывала ON — теперь восстанавливается в `onResume`; значок 🔒 снимается, т.к. CameraX сбрасывает фиксацию при закрытии камеры.
4. **Проверка сочетаний**: отложенный шаг прерванного прогона мог продолжить новый прогон — добавлен номер прогона.
5. **Pinch-zoom**: масштаб считался от отстающего `ZoomState` (рывки) — теперь от собственного значения жеста.

## Изменения 0.3.5 — PRO-инструменты

Кнопка **PRO** открывает меню; каждый пункт либо работает, либо пишет, почему недоступен на этом объективе.

| Инструмент | Условие (из Camera2) | Фото | Видео | СТЕК ×3 |
|---|---|---|---|---|
| Ручная экспозиция ISO/выдержка | `MANUAL_SENSOR` | да | — | — |
| Ручной фокус (∞…мин. дистанция, живой предпросмотр) | `MANUAL_SENSOR` и `LENS_INFO_MINIMUM_FOCUS_DISTANCE` > 0 | да | — | — |
| Баланс белого: пресеты | только режимы из `CONTROL_AWB_AVAILABLE_MODES` | да | да | да |
| Фиксация AE/AF: удержание пальца на превью, значок 🔒 | AF — всегда; AE — `CONTROL_AE_LOCK_AVAILABLE`; AWB — `CONTROL_AWB_LOCK_AVAILABLE` | да | да | да |
| Гистограмма (64 полосы, красные края = клиппинг > 1 %) | отдельный поток `ImageAnalysis` 640×480, ≤ 4 кадров/с | только обычный JPEG | — | — |

- Все параметры Camera2 собираются **одним набором** (`ProControls.plan`): `setCaptureRequestOptions` заменяет набор целиком, поэтому раньше ручная экспозиция и любые будущие параметры затирали бы друг друга.
- В режимах OEM HDR/Ночь/Портрет параметры Camera2 не применяются (как и раньше).
- При ручном фокусе касание превью замеряет только экспозицию и баланс белого — автофокус не борется с ручным.
- Если камера не принимает дополнительный поток гистограммы, он отключается автоматически и съёмка продолжается.
- **Температура в кельвинах не реализована:** для неё нужны `MANUAL_POST_PROCESSING` и матрицы цветокоррекции, поведение которых на прошивках сторонних производителей ненадёжно; сделано только то, что можно проверить.
- В диагностику добавлены AE/AWB lock, минимальная дистанция фокуса, калибровка и список пресетов WB по каждому объективу.

## Изменения 0.3.3 — СТЕК ×3 v2

Алгоритм `BurstDenoiser` переписан с сохранением API; старый режим усреднения доступен как `Options(linearMerge = false)`.

1. **Совмещение по пирамиде**: сдвиг до 64 px (было 24 px), с отдельной проверкой ±3 px на полном разрешении против алиасинга мелких текстур.
2. **Компенсация экспозиции**: коэффициент яркости в линейном свете, кадры вне 0,8…1,25 не используются.
3. **Пороги по реальному шуму** (оценка Immerkær) вместо фиксированных.
4. **Отклонение по блокам 16×16** + мягкие веса пикселей: малоконтрастное движение больше не «просачивается».
5. **Слияние в линейном свете** (обратная sRGB — приближение, тоновая кривая ISP неизвестна).
6. **Память**: результат пишется в буфер опорного кадра (−1 полный кадр ≈ 16 МБ при 2304×1728); **отмена** проверяется во время обработки.
7. **Метрики** в `Result.stats`: шум до/после, доля принятых блоков, коэффициенты экспозиции, время. **A/B**-сохранение опорного кадра.

Синтетический A/B (`tools/offline-check/bench.sh`, JVM на ПК, сцена 480×360, шум σ=6; **это не замер на телефоне**):

| Время 2304×1728 (ПК) | ~285–420 мс | ~320–370 мс |

Реальное качество на REVVL 7 Pro не измерено — для этого и сделан режим A/B.

## Сборка APK через GitHub с телефона

1. Создай пустой репозиторий в GitHub, например `revvl-camera-lab`.
2. Распакуй архив и загрузи **содержимое папки** `REVVL_Camera_Lab`, включая скрытую `.github/workflows/build-apk.yml`, в корень репозитория.
3. На вкладке **Actions** открой **Build Android APK** и нажми **Run workflow** (автосборки при `push` нет — только вручную). Для проверки без APK есть **Verify sources (no APK)**.
4. Workflow устанавливает Java/Gradle/SDK, запускает `testDebugUnitTest` и `assembleDebug`, затем загружает файл как **Artifacts → REVVL-Camera-Lab-debug**.
5. Скачай артефакт, распакуй `app-debug.apk` и установи его на телефон. Доверяй только собственному репозиторию и собранному тобой APK.

На компьютере открой проект в Android Studio (JDK 17, SDK 36) либо выполни `gradle :app:testDebugUnitTest :app:assembleDebug`. В ZIP нет Gradle Wrapper — он намеренно не нужен для настроенного workflow. Debug APK будет в `app/build/outputs/apk/debug/app-debug.apk` при успешной сборке.

## Как тестировать

В файле `TEST_PLAN.md` перечислены необходимые проверки JPEG, RAW, видеозаписи и нового режима «СТЕК ×3». Сравни те же неподвижные сцены в штатной камере, GCam и REVVL Camera Lab; оцени резкость, шум, смазывание и время съёмки. В меню **ДИАГНОСТИКА → Скопировать** доступен отчёт по фактически открытым камерам.

## Конфиденциальность и ограничения

- Нет разрешения INTERNET, аналитики и рекламных SDK; вся обработка кадров локальная.
- Сохраняются только фотографии и видео, которые пользователь сам снимает.
- Режим СТЕК не сохраняет исходные три кадра, только результат (и опорный кадр `_REF` при включённом A/B); при неудаче снимок не сохраняется.
- Соответствие реальным возможностям модулей REVVL 7 Pro определяется Camera2/CameraX, а не характеристиками Snapdragon в рекламе.
- На Android 16 ограничения прошивки могут скрывать ультраширик, макро, 50 Мп, RAW или ручной режим для сторонних камер.
