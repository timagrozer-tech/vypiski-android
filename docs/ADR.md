# Архитектурные решения (ADR)

Формат: контекст → решение → последствия. Статус «Принято», если не указано иное.

---

## ADR-0001. Офлайн-OCR: Tesseract 5 (Tesseract4Android), модели rus+eng в APK

**Контекст.** Нужен локальный OCR русского и английского без загрузки моделей из сети.
Google ML Kit Text Recognition v2 не поддерживает кириллицу (только латиница, китайский,
деванагари, японский, корейский), а модели Play Services скачиваются при установке.
PaddleOCR — нет готовой стабильной кириллической мобильной модели с проверенной лицензией.

**Решение.** Tesseract 5 через библиотеку Tesseract4Android (Apache-2.0, JitPack).
Модели `rus.traineddata`, `eng.traineddata`, `osd.traineddata` из `tesseract-ocr/tessdata_fast`
(Apache-2.0) хранятся в репозитории в `core/ocr/src/main/assets/tessdata/` (см. ADR-0011),
сверяются по SHA-256 задачей `verifyTessdata` перед каждой сборкой и копируются в `filesDir`
при первом запуске. Ориентация — OSD + проверка четырёх поворотов по средней уверенности при сбое OSD.

**Последствия.** +≈ 8 МБ к APK (fast-модели). Качество ниже облачных решений; метрики CER/WER
измеряются на тестовом наборе, а не заявляются. В интерфейсе OCR-текст помечается как
«распознанный, может содержать ошибки».

## ADR-0002. Компьютерное зрение: OpenCV 4.12 из Maven Central

**Решение.** `org.opencv:opencv:4.12.0` (Apache-2.0) — официальный AAR. Поиск границ:
уменьшение до 640 px → серый → `GaussianBlur` → `Canny` (адаптивные пороги по медиане) →
`dilate` → контуры → `approxPolyDP` → выпуклые четырёхугольники, оценка по площади и
прямоугольности; запасной путь — `HoughLinesP` + пересечения. Перспектива: `getPerspectiveTransform`
+ `warpPerspective` с целевым размером по длинам сторон (или по формату режима A4/A5/паспорт).
Тени: делим на размытый фон (морфологическое закрытие + медиана), нормализация.
Шум: `fastNlMeansDenoising` только для «Фото», для текста — `bilateralFilter` малого радиуса.
Ч/б: `adaptiveThreshold` (Sauvola-подобный) с защитой тонких штрихов — бинаризация не
применяется к областям цветных печатей (маска по насыщенности HSV), чтобы печати и подписи
не исчезали.

**Последствия.** +≈ 10 МБ на ABI; включаем ABI-splits (`arm64-v8a`, `armeabi-v7a`, `x86_64`).

## ADR-0003. PDF: PdfBox-Android для записи и правки, PdfRenderer для просмотра

**Контекст.** `android.graphics.pdf.PdfDocument` не умеет невидимый текстовый слой
(режим отрисовки 3), объединение, разделение, импорт.

**Решение.** `com.tom-roush:pdfbox-android` (Apache-2.0): страницы-изображения + невидимый
текст по координатам слов OCR (`RenderingMode.NEITHER`) с встроенным TTF-шрифтом с кириллицей
(Noto Sans, OFL-1.1, в assets). Просмотр и миниатюры — системный `PdfRenderer`.
Проверка целостности: повторное открытие файла, сверка числа страниц, наличие `%%EOF`.

## ADR-0004. Бизнес-логика в чистых Kotlin-модулях (`:core:common`, `:core:intelligence`, `:core:quality`; до этапа 2 v3.0 — `:core:domain`)

**Решение.** ФИО, именование, планировщик водяного знака, геометрия, автозатвор,
CER/WER, атомарная запись, журнал восстановления, пакетное именование — без Android API.
**Последствия.** Логика тестируется быстрыми JVM-тестами и проверяется даже без Android SDK.

## ADR-0005. Определение ФИО: правила + словарь, без нейросети

**Контекст.** Нужно офлайн, объяснимо, без лицензионных рисков; морфоанализаторы
(pymorphy и т.п.) недоступны под JVM без тяжёлых словарей.

**Решение.** Собственный экстрактор: нормализация OCR (латинские двойники → кириллица,
переносы, КАПС), шаблоны (Ф И О, И О Ф, Ф И.О., И.О. Ф, Ф И, поля «Фамилия/Имя/Отчество»,
«Ф.И.О.»), словарь имён (~400 форм-основ) с генерацией падежей, отчества и фамилии по
суффиксам, определение падежа и рода, контекстная оценка роли (субъект / подписант /
адресат / руководитель), частота упоминаний, позиция. Нормализация к именительному
падежу — только для надёжных моделей склонения (-ов/-ев/-ин/-ский/-ая и т.п.); иначе форма
сохраняется и выставляется флаг `normalizationReliable = false`.
Уверенность — функция разрыва оценок кандидатов. Пороги (из дизайн-системы):
≥ 0,90 — подставить; 0,60–0,89 — нужен выбор; < 0,60 — не подставлять.

## ADR-0006. DI вручную, без Hilt — **заменено ADR-0014**

Ручной `AppContainer` в `Application`. Меньше времени сборки и генерации кода, проще
проверка. Пересмотреть, если число зависимостей превысит ~40.

## ADR-0007. Водяной знак — только на экспорте

Знак не хранится в изображениях; рисуется при экспорте из `processed/`. Исключает
двойное нанесение и сохраняет оригиналы. Размещение — `WatermarkPlanner`:
нижняя левая область → сдвиг вверх по свободному полю в пределах нижней половины →
уменьшение до 10 pt (не меньше 70 % от заданного) → расширение страницы полем слева.

## ADR-0008. Защищённое хранилище: AES-256-GCM, ключ в Android Keystore

Ключ `KeyGenParameterSpec` с `setUserAuthenticationRequired` по выбору пользователя
(биометрия/PIN устройства). Файлы шифруются потоково блоками по 64 КиБ (GCM на блок,
номер блока в AAD) — работает с большими PDF без загрузки целиком.
`androidx.security:security-crypto` не используется (устарела).

## ADR-0009. Сборка APK в CI (GitHub Actions)

**Контекст.** В среде разработки ассистента нет Android SDK и доступа к Google Maven.
**Решение.** Workflow `.github/workflows/android.yml`: JDK 17, Android SDK, кеш Gradle,
`verifyTessdata`, unit-тесты, `verifyNoNetwork`, `assembleDebug`, артефакт APK;
инструментальные тесты на эмуляторе API 34 — отдельная задача. Ключи подписи Release —
только через секреты GitHub (`SIGNING_KEYSTORE_BASE64` и др.), в репозиторий не попадают.

## ADR-0010. Версии зависимостей

Фиксируются в `gradle/libs.versions.toml`. Выбраны стабильные версии, известные на момент
проектирования; Dependabot обновляет их еженедельно. Перед релизом — `./gradlew dependencies`
и проверка лицензий (`docs/LICENSES.md`).

## ADR-0011. OCR-модели хранятся в репозитории, а не скачиваются при сборке

**Контекст.** ТЗ требует, чтобы модели входили в состав приложения и не загружались из сети.
Загрузка при сборке (прежний вариант `fetchTessdata`) делает сборку зависимой от доступности
GitHub и позволяет незаметно получить другую версию модели.

**Решение.** Файлы `rus/eng/osd.traineddata` (tessdata_fast, коммит
`87416418657359cb625c412a48b6e1d6d41c29bd`, 18,5 МБ всего) лежат в
`core/ocr/src/main/assets/tessdata/`. Ожидаемые SHA-256 — в `core/ocr/tessdata.sha256`.
Задача `:core:ocr:verifyTessdata` подключена к `preBuild` и проваливает сборку при отсутствии
или несовпадении файла. Ассеты не сжимаются (`noCompress`), чтобы копирование при первом
запуске было быстрым.

**Последствия.** Репозиторий тяжелее на 18,5 МБ (Git LFS не требуется: файлы меняются редко).
Обновление моделей — осознанный коммит с новыми суммами и замером CER/WER до и после.

## ADR-0012. Проверка офлайн-режима на трёх уровнях

1. Манифест `:app` удаляет `INTERNET` (`tools:node="remove"`), если его принесёт библиотека.
2. `verifyNoInternet<Variant>` читает объединённый манифест и подключена к `assemble<Variant>` —
   APK с сетевым разрешением собрать нельзя.
3. `verifyNoNetworkDependencies` (корень) — список запрещённых групп (Firebase, GMS, OkHttp, ML Kit,
   аналитика, реклама) во всех runtime-classpath.
Дополнительно инструментальные тесты в CI запускаются на эмуляторе с выключенными Wi-Fi и данными.

## ADR-0013. Связка версий — по образцу Now in Android (план миграции)

**Контекст.** ТЗ v3.0 требует актуальные стабильные версии. Текущая связка (AGP 8.11.1, Kotlin 2.2.0,
Gradle 8.14.3) собирается в CI. Now in Android (Google, коммит 2026-10-20) использует AGP 9.3.2,
Kotlin 2.3.0, KSP 2.3.4, Hilt 2.59, Room 2.8.3, Gradle 9.7.1, compileSdk 37 / targetSdk 36.

**Решение.** На этапе 2 переходим на эту связку целиком (а не по одной библиотеке): она уже проверена
вместе в крупном проекте. AGP 9 встраивает Kotlin — плагин `org.jetbrains.kotlin.android` убирается.
CameraX 1.6.1 и Compose BOM 2026.06.00 — по camera-samples; OpenCV 4.13.0.
Миграция — отдельный коммит, критерий: CI зелёный, `:core:domain:test` 71/71.

## ADR-0014. Hilt вместо ручного контейнера

При 25 модулях и фоновых воркерах (WorkManager) ручной `AppContainer` требует вручную протягивать
зависимости через все фичи. Hilt (Apache-2.0) + `hilt-work` — стандарт и образец NiA.
Чистые JVM-модули (`intelligence`, `quality`, `common`) Hilt не используют и остаются тестируемыми
без Android.

## ADR-0015. Отказ от CanHub/Android-Image-Cropper и zynkware Document-Scanning SDK

CanHub — только прямоугольная обрезка на View; zynkware — не поддерживается с 2023 г., OpenCV 4.4,
RxJava. Свой редактор углов на Compose + `domain.geometry` (гомография уже покрыта тестами), свой
детектор на OpenCV (ADR-0002).

## ADR-0016. Два уровня OCR: «Быстрый» в APK, «Высокая точность» — офлайн-пакет

`tessdata_fast` (rus+eng+osd, 17,7 МБ) встроен. `tessdata_best` (rus+eng, 30,7 МБ) — файл
пакета `scanner291-ocr-best.zip` с манифестом SHA-256, собирается в CI и импортируется пользователем
через SAF (без сети). Выбор режима — в профиле документа; автоматически «Высокая точность» не
включается, если пакет не установлен. Метрики CER/WER и время — для обоих режимов на одном наборе.

## ADR-0017. Безопасный разбор недоверенных PDF

PdfBox-Android не обновлялся с 2023 г. Меры:
1. Просмотр и миниатюры импортированных PDF — системный `PdfRenderer`, не PdfBox.
2. PdfBox открывает чужие PDF только для операций правки, в отдельном процессе
   (`android:process=":pdf"`) с ограничением времени и памяти (`MemoryUsageSetting.setupTempFileOnly`),
   падение процесса не роняет приложение.
3. Лимит размера импорта (по умолчанию 200 МБ) и числа страниц (2000), проверка сигнатуры `%PDF-`.
4. XFDF/FDF и XML-метаданные не разбираются.
5. Пересмотр решения, если появится поддерживаемая Apache-2.0 альтернатива.
